# 微信支付模块说明

> 适用范围：`github.com/jcbowen/wego/payment`，微信支付 API V3。

## 一、初始化

```go
import (
    "github.com/jcbowen/wego"
    "github.com/jcbowen/wego/payment"
)

payCfg := &payment.Config{
    AppID:        "wx1234567890",
    MchID:        "1900000001",
    APIV3Key:     "32位APIv3密钥",
    CertSerialNo: "商户API证书序列号",
    PrivateKey:   privateKeyPEM, // apiclient_key.pem 内容
    NotifyURL:    "https://example.com/pay/notify",
    // 公钥模式（官方推荐，可选）
    PublicKeyID: "PUB_KEY_ID_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    PublicKey:   publicKeyPEM, // pub_key.pem 内容
}

client := wego.New(payCfg).Payment()
```

> ⚠️ `payment.NewClient` / `NewClientWithStorage` 在配置非法时会 `log.Panic` 终止进程。
> 本仓库是**依赖库**，不应越权决定宿主进程生死，因此新增了返回 error 的构造函数：
>
> ```go
> client, err := payment.NewClientE(payCfg)                  // 默认文件存储
> client, err := payment.NewClientWithStorageE(payCfg, store) // 自定义存储
> ```
>
> 建议业务侧统一改用 `NewClientE` / `NewClientWithStorageE`；
> 旧的 `NewClient` / `NewClientWithStorage` 已标注 `Deprecated`，仅为兼容保留。
>
> 默认存储目录为 `./runtime/wego_storage`，需确保进程对该目录有读写权限。

## 二、验签模式：平台证书与微信支付公钥

微信支付提供两种等价的验签凭据，本库**同时支持**，并按下列规则自动选择。

| 配置情况 | 请求行为 | 验签行为 |
|---|---|---|
| 只配平台证书（不填 `PublicKeyID`/`PublicKey`） | 不发 `Wechatpay-Serial` 请求头，与旧版本行为一致 | 应答与回调均使用平台证书验签 |
| 只配公钥 | 请求头带 `Wechatpay-Serial: PUB_KEY_ID_xxx` | 应答与回调按响应头判定，公钥 ID 用公钥，证书序列号则尝试下载平台证书 |
| 两者都配 | 请求头带 `Wechatpay-Serial: PUB_KEY_ID_xxx`，**优先公钥** | 同上，仍以响应头为准，灰度期可自动回退到平台证书 |

### 为什么必须以响应头为准

微信支付的应答与回调响应头都会携带 `Wechatpay-Serial`：

- 以 `PUB_KEY_ID_` 开头 —— 本次签名使用**微信支付公钥**
- 其它值 —— 本次签名使用**平台证书**

官方切换灰度期内，**回调场景**由微信按比例随机决定用哪种密钥签名（商户无法控制），
因此必须同时兼容两条链路。本库在 `resolveVerifyPublicKey` 中统一处理，应答验签与回调验签共用该逻辑。

### 迁移建议

1. 现有平台证书模式无需改动，继续可用。
2. 新接入或准备切换的商户号，建议在商户平台申请微信支付公钥，填入 `PublicKeyID` + `PublicKey`。
3. 切换灰度期间保留平台证书下载能力（本库默认保留），灰度完成后平台证书即不再被调用。

> 注意：`CertSerialNo` 是**商户 API 证书序列号**，用于请求签名，与验签凭据无关，**始终必填**。

## 三、接口一览

| 方法 | 说明 | 官方文档 |
|---|---|---|
| `JSAPIPay` | JSAPI / 小程序下单，返回 `prepay_id` | /v3/pay/transactions/jsapi |
| `H5Pay` | H5 下单，返回 `h5_url` | /v3/pay/transactions/h5 |
| `NativePay` | Native 扫码下单，返回 `code_url` | /v3/pay/transactions/native |
| `AppPay` | App 下单，返回 `prepay_id` | /v3/pay/transactions/app |
| `CodePay` | 付款码支付下单（B扫C），同步返回订单结果；scene_info/store_info 必填，官方产品页提示以 V2 文档为准 | /v3/pay/transactions/codepay |
| `QueryOrder` | 按商户订单号查单 | /v3/pay/transactions/out-trade-no/{out_trade_no} |
| `QueryOrderByTransactionID` | 按微信支付订单号查单 | /v3/pay/transactions/id/{transaction_id} |
| `CloseOrder` | 关闭未支付订单 | /v3/pay/transactions/out-trade-no/{out_trade_no}/close |
| `ReverseOrder` | 撤销订单（付款码配套，USERPAYING 在途交易只能撤销；官方提示灰度中） | /v3/pay/transactions/out-trade-no/{out_trade_no}/reverse |
| `Refund` | 申请退款 | /v3/refund/domestic/refunds |
| `RefundQuery` | 按商户退款单号查退款 | /v3/refund/domestic/refunds/{out_refund_no} |

| `BuildAppPayParams` | 生成 App 调起支付参数 | 调起支付签名 |
| `EncryptSensitiveData` | RSAES-OAEP 加密敏感字段 | 敏感信息加密 |
| `EncryptSerialNo` | 取当前加密所用公钥 ID / 证书序列号 | 敏感信息加密 |

| `ProfitSharingAmounts` | 查询剩余待分金额 | /v3/profitsharing/transactions/{id}/amounts |
| `VerifyNotification` | 回调验签并解密资源 | 通知验签 |
| `DecryptNotificationResource` | 仅解密回调资源 | 通知解密 |

## 四、完整调用示例

### 下单并调起支付

```go
ctx := context.Background()

prepay, err := client.JSAPIPay(ctx, &payment.JSAPIRequest{
    Description: "商品描述",
    OutTradeNo:  "ORDER_20240101_001",
    Amount:      payment.Amount{Total: 100}, // 单位：分
    Payer:       payment.Payer{OpenID: "oUpF8uMuAJO_M2pxb1Q9zNjWeS6o"},
})
if err != nil {
    return err
}

params, err := client.BuildJSAPIPayParams(prepay.PrepayID)
if err != nil {
    return err
}
// params 可直接返回给小程序 wx.requestPayment 或公众号 JS-SDK
```

`BuildJSAPIPayParams` 的签名串为 `appId\ntimeStamp\nnonceStr\npackage\n`，
签名类型固定 `RSA`，输出字段名为 `appId`、`timeStamp`、`nonceStr`、`package`、`signType`、`paySign`。

### Native 扫码支付

```go
resp, err := client.NativePay(ctx, &payment.NativeRequest{
    Description: "商品描述",
    OutTradeNo:  "ORDER_20240101_001",
    Amount:      payment.Amount{Total: 100},
})
// resp.CodeURL 需由商户侧转换为二维码图片展示给用户
```

### App 支付

```go
prepay, err := client.AppPay(ctx, &payment.AppRequest{
    Description: "商品描述",
    OutTradeNo:  "ORDER_20240101_001",
    Amount:      payment.Amount{Total: 100},
})
if err != nil {
    return err
}

params, err := client.BuildAppPayParams(prepay.PrepayID)
// params 交给客户端 SDK：appid / partnerid / prepayid / package / noncestr / timestamp / sign
```

App 签名串为四行 `appid\ntimestamp\nnoncestr\nprepayid\n`，**不包含** `partnerid` 与 `package`；
客户端字段名全小写，大小写敏感。

### 关单

```go
// 用户取消或订单超时未支付
if err := client.CloseOrder(ctx, "ORDER_20240101_001"); err != nil {
    return err
}
```

成功时微信返回 `204 No Content`，本库不返回任何结构体。

### 退款与查退款

```go
refund, err := client.Refund(ctx, &payment.RefundRequest{
    OutTradeNo:  "ORDER_20240101_001",
    OutRefundNo: "REFUND_20240101_001",
    Reason:      "用户申请退款",
    Amount:      payment.RefundAmount{Refund: 100, Total: 100},
})
if err != nil {
    return err
}

// 退款是异步的，需轮询确认最终状态
result, err := client.RefundQuery(ctx, "REFUND_20240101_001")
if err != nil {
    return err
}
if result.Status == "SUCCESS" {
    // 退款成功
}
```

### 回调处理

```go
func NotifyHandler(w http.ResponseWriter, r *http.Request) {
    body, _ := io.ReadAll(r.Body)

    notification, plain, err := client.VerifyNotification(r.Context(), r.Header, body)
    if err != nil {
        w.WriteHeader(http.StatusUnauthorized)
        return
    }

    switch notification.EventType {
    case "TRANSACTION.SUCCESS":
        // plain 为解密后的支付结果 JSON
    case "REFUND.SUCCESS":
        // 退款成功
    }

    w.WriteHeader(http.StatusNoContent)
}
```

回调验签同样按 `Wechatpay-Serial` 自动选择公钥或平台证书，无需业务侧关心。

### 敏感信息加密

```go
// 优先使用配置的微信支付公钥，未配置时使用最新平台证书
name, err := client.EncryptSensitiveData(ctx, "张三")
```

算法为 RSAES-OAEP（SHA-1 + MGF1-SHA1），输出 Base64 密文可直接作为接口字段值。
分账等接口会自动把请求头 `Wechatpay-Serial` 设置为**实际加密所用**的公钥 ID 或证书序列号，无需手工指定。

### 账单下载

```go
bill, err := client.ApplyTradeBill(ctx, &payment.BillRequest{
    BillDate: "2026-10-14",
    BillType: "ALL",     // ALL / SUCCESS / REFUND
    TarType:  "GZIP",    // 不填则不压缩
})
if err != nil {
    return err
}

// DownloadBill 会自动用返回的 hash_value 做 SHA1 完整性校验
data, err := client.DownloadBill(ctx, bill.DownloadURL, bill.HashValue)
```

资金账单用 `ApplyFundFlowBill`，额外支持 `AccountType`（BASIC / OPERATION / FEES）。
下载链接 5 分钟内有效，微信次日 9 点生成前一天对账单，建议 10 点后获取。

### 分账

```go
// 接收方姓名为敏感字段，需加密
name, err := client.EncryptSensitiveData(ctx, "张三")
if err != nil {
    return err
}

resp, err := client.ProfitSharing(ctx, &payment.ProfitSharingRequest{
    TransactionID:   "4200001234202401011234567890",
    OutOrderNo:      "PS_20240101_001",
    UnfreezeUnsplit: true,
    Receivers: []payment.ProfitSharingReceiver{
        {Type: "MERCHANT_ID", Account: "1900000109", Name: name, Amount: 100, Description: "分给商户A"},
    },
})
if err != nil {
    return err
}

// 分账为异步处理，需查询最终结果
result, err := client.ProfitSharingQuery(ctx, "PS_20240101_001", "4200001234202401011234567890")
if err != nil {
    return err
}
if result.State == "FINISHED" {
    // 处理完毕，逐个检查 result.Receivers[i].Result
}
```

其余能力：`ProfitSharingReturn` / `ProfitSharingReturnQuery`（分账回退）、
`ProfitSharingUnfreeze`（解冻剩余资金）、`ProfitSharingAmounts`（查询剩余待分金额）。

## 五、错误处理

- 请求参数为空、订单号/退款单号为空、金额非正数：直接返回明确错误，不发请求。
- 应答验签失败、回调时间戳偏差超过 5 分钟：返回错误，业务侧应拒绝处理。
- 响应头为 `PUB_KEY_ID_` 但未配置公钥：返回「响应使用微信支付公钥签名，但当前未配置 PublicKeyID/PublicKey」，
  提示接入方补齐配置。

### 区分微信支付业务错误

4xx/5xx 时微信会返回结构化错误体 `{"code":"...","message":"...","detail":{...}}`。
本库会将其解析为 `*payment.APIError`，业务可用 `AsAPIError` / `errors.Is` 做差异化处理：

```go
err := client.CloseOrder(ctx, "ORDER_001")
if apiErr, ok := payment.AsAPIError(err); ok {
    switch apiErr.Code {
    case "ORDERPAIDCLOSE", "ORDER_PAID":
        // 订单已支付，不能关闭 —— 属正常业务分支，不应当作故障
    case "ORDER_NOT_EXIST":
        // 订单不存在
    default:
        log.Printf("微信支付错误 %s: %s", apiErr.Code, apiErr.Message)
    }
}

// 也支持 errors.Is 按错误码比较
if errors.Is(err, &payment.APIError{Code: "NO_AUTH"}) { /* 无权限 */ }
```

`APIError` 携带 `StatusCode`、`Code`、`Message`、`Detail`、`RawBody` 与 `Header`（含 `Wechatpay-Request-ID`，便于提工单）。
响应体不是微信错误格式（如网关返回 HTML）时回退为普通错误。

### 预定义错误

| 错误 | 含义 |
|---|---|
| `payment.ErrNoEncryptKey` | 未配置公钥且平台证书不可用，无法加密敏感信息 |
| `payment.ErrCertDownloadFailed` | 平台证书下载/解密失败或返回空列表 |
| `payment.ErrSignatureHeaderMissing` | 响应缺少微信支付签名头 |

## 六、注意事项

### 6.1 验签模式选择（重要）

- 微信支付官方已**推荐使用微信支付公钥**：公钥无过期时间，而平台证书每 5 年需更换一次；
  且**新申请的商户号由平台随机分配**证书方案或公钥方案。
- 若商户号被分配到公钥方案，`/v3/certificates` 将取不到证书，只依赖平台证书会导致整条链路不可用。
  **建议所有接入方都配置 `PublicKeyID` + `PublicKey`。**
- 灰度期内**不要**只按本地配置切换验签凭据：回调场景由微信按比例随机决定用哪种密钥签名，
  必须按响应头 `Wechatpay-Serial` 路由（本库已在 `resolveVerifyPublicKey` 中统一处理）。
- 只有平台证书模式时，本库不会发送 `Wechatpay-Serial` 请求头；配置公钥后才会声明 `PUB_KEY_ID_xxx`。

### 6.2 容易混淆的两个"序列号"

| 配置项 | 含义 | 是否必填 |
|---|---|---|
| `CertSerialNo` | **商户 API 证书序列号**，用于 Authorization 请求签名 | 必填 |
| `PublicKeyID` | **微信支付公钥 ID**（`PUB_KEY_ID_xxx`），用于应答/回调验签、敏感信息加密 | 强烈建议 |

两者用途完全不同，不能互相替代。

### 6.3 回调处理

- **必须应答**。处理成功后返回 `200` 或 `204`（推荐带 `{"code":"SUCCESS","message":"成功"}`，见常量
  `payment.NotificationAckJSON`）；返回 4xx/5xx 或不响应，微信会按
  `15s/15s/30s/3m/10m/20m/30m/30m/30m/60m/3h/3h/3h/6h/6h/6h` 的频率**重试 15 次**。
- **必须幂等**。同一通知可能重复投递，业务侧需按 `out_trade_no` + `event_type` 去重，
  不能仅依赖 5 分钟时间戳窗口（窗口内仍可重放）。
- 务必在**验签通过后再解密**并使用数据；解密失败或数据不合法应返回失败让微信重试。
- 回调处理耗时建议控制在数秒内，超时会被判为失败并触发重试；复杂逻辑应入队异步处理。

### 6.4 订单与退款语义

- `CloseOrder` 只能关闭**未支付**订单；已支付订单会返回 `ORDERPAIDCLOSE`（需改为走退款）。
- 退款是**异步**的：`Refund` 返回成功仅表示受理，最终状态必须用 `RefundQuery` 确认。
- `RefundQuery` 只能按商户退款单号查询，退款单号需业务侧自行保证唯一。
- 金额单位统一为**分**，且必须为正整数；`Refund` 会校验退款金额不超过原订单金额。

### 6.5 订单号命名

- 商户订单号、退款单号会作为 **URL 路径**发送，本库已用 `EscapedPath()` 保证签名路径与实际请求路径一致。
- 但为降低排查成本，**建议只使用大小写字母、数字、下划线和短横线**，避免 `/`、空格、中文等字符。

### 6.6 分账

- 分账为异步处理，`ProfitSharing` 返回 `PROCESSING` 后需用 `ProfitSharingQuery` 轮询到 `FINISHED`，
  再逐个检查 `Receivers[i].Result`（`PENDING` / `SUCCESS` / `CLOSED`）。
- 接收方类型为 `PERSONAL_OPENID`（个人）时，**姓名必填且必须加密**；
  类型为 `MERCHANT_ID`（商户号）时无需姓名，本库此时也不会声明 `Wechatpay-Serial` 请求头。
- **加密所用密钥必须与请求头 `Wechatpay-Serial` 声明的一致**，否则微信会报「加密密钥与请求头不一致」。
  不要自行缓存密文跨密钥轮换期复用；如需手工加密，请用 `EncryptSerialNo` 取当前序列号并同时设置请求头。
- 分账解冻、回退等操作涉及的金额字段同样单位为分。

### 6.7 账单

- 微信在次日 9 点开始生成前一天对账单，**建议次日 10 点后获取**。
- `download_url` 有效期仅 **5 分钟**，获取后应立即下载。
- `tar_type=GZIP` 时 `DownloadBill` 返回的是压缩流，业务侧需自行解压。
- 账单下载响应**不含微信签名**，本库已跳过验签（官方明确要求），但会用 `hash_value` 做 SHA1 完整性校验。

### 6.8 平台证书与限流

- 首次使用平台证书模式的请求会触发一次 `/v3/certificates` 下载，之后缓存到存储与内存。
- 该接口有频率限制：本库对下载做了串行化，且失败后 **1 分钟内不重试**，避免被限流。
- 证书下载接口本身**不做验签**（验签依赖证书，属"先有鸡后有蛋"，官方 SDK 同样处理）。
- 证书解密依赖 `APIV3Key`，必须是 **32 字节**，否则会报解密失败。

### 6.9 生产环境配置

- 默认 `http.Client` 超时为 30 秒；账单下载等大响应建议通过
  `SetHTTPClient` 注入自定义客户端（含超时、连接池、重试）。
- 默认日志器会打印请求头与请求体，**生产环境建议注入脱敏日志器**（`SetLogger`）。
- 商户私钥、API V3 密钥属于高敏感凭据，不要写入代码仓库，建议走配置中心或环境变量。
- 4xx/5xx 响应本库只解析错误码**不做验签**，因此不要把失败响应内容当作可信数据使用。

### 6.10 尚未覆盖的能力

以下接口当前未实现，有需要可按需扩展：

- 合单支付、小程序/公众号之外的合单能力
- 代金券/商家券、支付即服务、电子发票
- 跨境支付（该场景的 App 调起签名串与国内版不同）
- 转账（商家转账到零钱）、来账识别
- 微信支付分、先享卡等增值能力
